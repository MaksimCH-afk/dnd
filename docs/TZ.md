# ТЗ: Текстовое НРИ (соло) — local-first PWA с движком состояния и LLM-связкой

**Версия ТЗ:** 1.1 (сборко-агностичная переработка)
**Тип проекта:** одиночное приложение для одного пользователя (self-hosted, local-first)
**Язык игры:** русский (всё — UI, промпты, контент — на русском)
**Задача:** заменить «проект в Клоде + .md-файлы» на самостоятельное приложение, которое ведёт ту же игру **для персонажа любого направления** (не только мага), синхронизируется между ПК и Android-планшетом и **архитектурно исключает** пять известных проблем (раздел 2).

> **Что нового в 1.1:** модель состояния и UI больше не предполагают мага. Введён общий слой + подключаемые модули-способности по направлению (бой, магия, интрига, вера, ремесло, влияние). Добавлены подсистемы движка из лора, выпавшие в 1.0 (создание персонажа, репутация, экономика, время, контракты, локации, прогрессия, отложенные последствия), расширён бой, добавлено распределение «правила: движок vs промпт».

---

## 1. Цель и общая идея

Приложение ведёт текстовую ролевую игру в эпическом фэнтези-мире (правила — в существующих файлах `world.md`, `magic.md`, `religions.md`, `systems.md`, `progression.md`, `master.md`, `creation.md`, `commands.md`). Мастера-рассказчика играет LLM через OpenRouter.

**Принцип 1 — разделение ролей.**
- **Движок** (детерминированный, источник истины) хранит состояние структурно, применяет изменения транзакционно, бросает кости, считает цены/время/бой, собирает контекст, версионирует сейвы. Не «придумывает».
- **LLM** (рассказчик/режиссёр) получает только нужный срез состояния, генерирует прозу и **предлагает** изменения операциями (tool-calls). Не хранилище правды и не бросает кости.

**Принцип 2 — сборко-агностичность.** Персонаж — любое направление из `creation.md` (военный, наёмник, ремесленник, торговец, путешественник, преступник/шпион, академик/маг, отшельник, жрец) и гибриды (боевой маг и т.п.). Движок, UI и промпты строятся вокруг **общего слоя + модулей способностей**, которые включаются по сборке персонажа. Магия — один из модулей, а не основа системы.

## 2. Проблемы и проектные требования

### 2.1 Пять багов, которые ТЗ обязано закрыть (критерии успеха)

| # | Проблема | Корневая причина | Механизм решения |
|---|----------|------------------|------------------|
| 1 | Однообразие сюжета на длинной дистанции (повтор поворотов на 300+ дней) | Нет записи «что уже было»; новизна на плечах одной модели | Хроника арок с тегами + Режиссёр + мир-симуляция + отложенные последствия (seeds) |
| 2 | Забывание мелких деталей, ошибки NPC | Лоссовый пересказ состояния при сохранении | Канон в БД + RAG-ретривал релевантных сущностей перед каждой генерацией |
| 3 | NPC знают то, чего знать не могут | Утечка всеведущего рассказчика | Модель знания (scoping) + подсистема узнавания (репутация/известность) |
| 4 | Дрейф характеров/описаний | Лоссовый пересказ личностей | Запертые карточки NPC: идентичность неизменяема без явной причины |
| 5 | Потеря предметов при сохранении-загрузке | Инвентарь регенерируется по памяти | Дельта-операции; инвентарь никогда не пересобирается заново |

### 2.2 Проектные требования (не баги, но обязательны)

- **R1. Сборко-агностичность** — поддержка всех направлений; модули включаются по сборке; UI/статус/промпты адаптируются (см. разделы 4, 7, 18).
- **R2. Детерминированная механика на стороне движка** — кости, цены, бой, время, прогрессия считает движок, не LLM (раздел 7, 9).
- **R3. Версионируемые сейвы и мульти-кампании** (раздел 15).
- **R4. Русский во всём**, сильный русский recall у эмбеддера (разделы 5/10).

## 3. Архитектура и развёртывание

**Модель: local-first PWA + git + тонкий backend.**

```
┌─────────────────────────────────────────────┐
│  PWA (браузер: ПК и Android, один и тот же)   │
│  • UI чата + адаптивные панели состояния      │
│  • Движок состояния (TS/JS): механика, дельты │
│  • RAG/эмбеддинги локально (transformers.js)  │
│  • git-клиент (isomorphic-git) → pull/commit  │
└───────────────┬───────────────────────────────┘
                │ (только LLM-вызовы и эмбеддинг при необходимости)
                ▼
┌─────────────────────────────────────────────┐
│  Тонкий backend (Docker), stateless           │
│  • прокси к OpenRouter (хранит API-ключ)      │
│  • CORS, ретраи/бэкофф, фоллбэк-модель         │
│  • НЕ хранит игровое состояние                │
└───────────────┬───────────────────────────────┘
                ▼
        OpenRouter API (модели по ролям)

Состояние и синхронизация:
   git-репозиторий  ←→  PWA на ПК
                    ←→  PWA на планшете
   (источник истины — структурный JSON; md — экспорт для чтения)
```

**Почему так:** один веб-апп работает в браузере и на ПК, и на Android → «открыл и продолжил с любого устройства» без порта под платформу. Состояние в git → бесплатное версионирование, дифф, откат, кросс-девайс синк. Backend нужен только чтобы не светить ключ и обойти CORS; stateless, пакуется в Docker, поднимается на ПК или always-on коробке. Режим «PWA зовёт OpenRouter напрямую с локально сохранённым ключом» — опционально (для игры с планшета при выключенном ПК), переключается в настройках.

**Стек (ориентир):** TypeScript + лёгкий фреймворк (Svelte/React), PWA (manifest + service worker, офлайн-кэш); `isomorphic-git`; `transformers.js` (`bge-m3`/`multilingual-e5`); backend на Node/Python (один прокси-эндпоинт + конфиг); IndexedDB как локальный кэш состояния между синками.

## 4. Модель состояния (источник истины) — сборко-агностичная

Состояние = типизированные сущности в JSON (по файлу/коллекции в git-репо) + рендер в md для чтения. У схемы есть `schema_version` (раздел 15).

### 4.1 Общий слой персонажа (есть у всех направлений)

`character.core`:
- идентичность: имя (явное/настоящее), раса, возраст, направление(я);
- **скрытые атрибуты** (STR/DEX/CON/INT/PER/CHA) — движок, игроку не показываются;
- **HP** (тек/макс), **выносливость** (тек/макс) — у всех;
- статусы/эффекты, ранения (с примерным сроком заживления);
- **навыки и особенности словами** (`features[]`: «Опытный переговорщик», «Привычен к холоду», «Фехтовальщик») и специализации;
- **репутация** по фракциям (уровнями, см. 9.4) и «известность»;
- инвентарь и капитал (см. 4.3);
- отношения, обязательства, таймеры (общие, см. 4.4).

### 4.2 Модули способностей (включаются по сборке)

Каждый модуль — отдельная структура в `character.modules`, присутствует, только если сборка его даёт. UI, статус и промпты рендерят лишь активные модули.

| Модуль | Кому (направление) | Что хранит | Лор |
|--------|--------------------|-----------|-----|
| **magic** | академик/маг, жрец-маг, тёмные дорожки | состояние Силы (enum), тип мага (черпающий/своесильный), владение школами + мастерство (словом), тёмные дуги (описанием) | `magic.md` |
| **combat_mastery** | военный, наёмник, боевой маг | владение оружием/стилями, боевые особенности, скрытый боевой уровень | `systems.md` |
| **intrigue** | преступник/шпион, агент культа Обмана | прикрытия/личины, уровень «след/подозрение» (heat), связи в криминале, тайники-схроны | `world.md`, `religions.md` |
| **faith** | жрец, адепт культа | бог/домен, статус в культе, вера/служение (грех/отступничество ослабляют дар) | `religions.md`, `magic.md` |
| **craft** | ремесленник | ремесло + уровень (подмастерье→мастер), статус в гильдии, рецепты/шедевры, мастерская | `progression.md` |
| **influence** | знать, путь влияния | титулы, владения, статус при дворе, политические связи | `world.md` |

**Маппинг направление → модули (дефолт, расширяемо):**
- военный → combat_mastery (+influence если из знати);
- наёмник → combat_mastery (+intrigue-связи лёгкие);
- преступник/шпион → intrigue (+combat_mastery лёгкий);
- академик/маг → magic;
- боевой маг → magic + combat_mastery;
- жрец → faith (+magic, если жрец-маг домена);
- ремесленник → craft;
- торговец → influence-лайт + связи;
- отшельник/путешественник → по предыстории (часто природная magic или выживание-особенности).

> Проверка таланта на старте (см. раздел 5) решает, включается ли модуль **magic** вообще. Нет таланта → магии нет, и это нормальная, полноценная сборка.

### 4.3 Инвентарь и капитал (решает №5)

`inventory.items[]`: `{id, name, qty, charges?, slot: надето|сумка|схрон, magical: bool, notes, acquired_day}`. Капитал — поле + журнал последних операций. Изменения только дельта-операциями (раздел 7.2 валидатора); список **никогда** не регенерируется по памяти.

### 4.4 Мир, сюжет, связи (общие сущности)

- **npc** — карточки (4.6).
- **facts** — атомарные факты со scope знания (4.5): `{id, text, scope, known_by, tags, created_day}`.
- **relationships** — рёбра: `{from, to, axis: доверие|страх|долг|вражда|романтика, level, notes}`.
- **promises_debts** — обещания, сделки, долги (с дедлайнами).
- **contracts** — квесты/задания (9.7).
- **locations** — места (9.8).
- **timers** — `{label, due_day, type, payload}`.
- **chronicle** — append-only лог ходов (день, локация, событие, применённые дельты).
- **arcs** — арки с тегами (раздел 12).
- **seeds** — отложенные последствия (9.10).
- **world_state** — фракции/регионы/мировые часы (раздел 12).
- **session** — точка возврата: момент, погода, время суток, NPC в сцене, открытые ветки.

### 4.5 Модель знания (решает №3)

У каждого факта — `scope` ∈ {`public`, `npc:<id>`, `player`, `secret`} и `known_by[]`. Скрытое (настоящее имя, тёмная школа, прикрытие шпиона, тайные цели) по умолчанию **не** `public`. Узнавание — производное от факта в `known_by` конкретного NPC **и** от репутации/известности (9.4). Перед репликой NPC движок собирает ограниченный контекст = `public` + память этого NPC + наблюдаемое в сцене; скрытые поля героя физически не попадают в его рассуждение.

### 4.6 Карточки NPC (решает №4)

- **Запертое ядро (immutable-by-default):** раса, возраст, сословие, роль, речевой регистр, ядро характера, мотивация, секрет, внешность. Меняется только операцией `npc.alter_core` с причиной (старение, увечье, сюжетный слом).
- **Живой слой (mutable):** настроение, последние взаимодействия, сдвиги отношений, что знает (`known_by`), местоположение.

NPC в сцене → движок вставляет **полное запертое ядро дословно** + релевантный живой слой. Дрейф невозможен: модель не «вспоминает» личность, а получает её каждый ход.

## 5. Создание персонажа (спека движка)

«Новая игра» = детерминированный флоу по `creation.md`. Все броски — скрытые, на стороне движка.

1. **Основы:** раса, возраст, направление (выбор игрока) → задают физиологию, скрытые базовые атрибуты + небольшой скрытый бросок, срок жизни, восприятие в обществе.
2. **Проверка таланта к магии (скрытая):** определяет, включается ли модуль `magic`. Нет таланта → магии нет (валидная сборка). Есть → тип мага (черпающий/своесильный) + **одна открытая школа по направлению** на уровне «Новичок» (академик→стихийная, жрец→божественная домена, друид→природная) или начальная форма выбранной тёмной дорожки. Редкие/закрытые школы (аура, иллюзии, разум) на старте недоступны.
3. **Потолок старта (жёсткое правило):** способный, но не прокачанный. Никаких легендарных стартов, мастерских рангов, готовых высоких статусов. Вор/шпион стартует обычным человеком с навыками, не главой гильдии — максимум «знакомство/след» в криминале.
4. **Стартовая репутация:** «светлый» старт → нейтрально у всех (с лёгкими перекосами от расы/направления: дроу/орки — недоверие, экс-солдат ближе военным). Тёмная сторона (кровавая/тёмная магия, некромантия, культы) → подозрительный, а не нейтральный.
5. **Капитал и экипировка:** по направлению + небольшой скрытый бросок удачи. Малый капитал — норма.
6. **HP/выносливость:** из CON + поправка направления (ориентиры `systems.md`), скрыто.
7. **Стартовая локация:** логична из направления (таблица `creation.md`).
8. **Стартовый хук:** мягкий, не принудительный (`[ситуация]+[возможность/проблема]+[срочность]+[риск/награда]`); держать 2–3 скрытых хука в `seeds`.
9. **Создать `session`** (точка возврата) и первую сцену.

Загрузка/импорт существующего сейва — раздел 15 (создание пропускается).

## 6. Роли моделей и конфиг

Назначение модели на роль — в конфиге (`config.models`), значение = OpenRouter model ID. **Все подсистемы v1.1 (бой, экономика, время, репутация, контракты, локации, прогрессия, seeds) — детерминированный движок, а не вызовы модели**, поэтому число LLM-ролей не растёт. Дефолты:

| Роль | Дефолт | Альтернатива/переключатель | Назначение | Вызов |
|------|--------|----------------------------|------------|-------|
| **Ведущий (narrator)** | `qwen/qwen3-next-80b-a3b-instruct:free` | `nousresearch/hermes-3-llama-3.1-405b:free` (богаче проза/RP) | Проза + предложенные дельты (tool-calls) | Каждый ход |
| **Нормализатор/валидатор** | `google/gemma-4-31b-it:free` | `openai/gpt-oss-120b:free` (тяжелее) | Нормализует tool-call'ы нарратора в чистые `Op[]`; семантически ловит утечки знания (№3). Детерминированные проверки — в движке (7.3) | Каждый ход |
| **Режиссёр + мир-симуляция** | `nvidia/nemotron-3-super-120b-a12b:free` | `nvidia/nemotron-3-ultra-550b-a55b:free` (апгрейд для крупных арок) | Планирует арки из неиспользованной матрицы; тикает мир; обрабатывает seeds | Между арками / по мировым часам (не в горячем пути) |
| **Эмбеддинги (RAG)** | локальный `bge-m3` (или `multilingual-e5`), сменный | — | Векторизация/поиск фактов, карточек, хроники | При записи и перед сборкой контекста |
| **Фоллбэк-нарратор** | `cognitivecomputations/dolphin-mistral-24b-venice-edition:free` | — | Профиль для тёмных сцен при отказе основной модели. **Контекст 33K → движок жёстко обрезает промпт** (сцена + активные модули + NPC рядом; без выдержек правил) | По переключению/при отказе |

**Опциональные роли (по желанию, не в MVP):**
- **Роутер тёмных сцен** — `nvidia/nemotron-3.5-content-safety:free` **как классификатор «темноты» сцены для упреждающего переключения на фоллбэк-профиль, НЕ как цензор** (раздел 17). Альтернатива — роутинг по тегам/ключевым словам без модели.
- **NPC-спавн-хелпер** — по умолчанию спавн делает нарратор операцией `npc.spawn`; выносить в микромодель (`nvidia/nemotron-3-nano-30b-a3b:free` / `openai/gpt-oss-20b:free`) только если страдает латентность.
- **Атмосферная музыка (фаза 2+)** — `google/lyria-3-clip-preview` (платно, ~$0.04/клип) для фонового эмбиента под регион/сцену. Необязательный флёр.

**Не брать ни на одну роль с игровым текстом:** `openrouter/owl-alpha`, `poolside/laguna-m.1:free` — карточки предупреждают, что промпты/ответы могут логироваться и использоваться для обучения; для приватной игры со зрелым контентом неприемлемо.

Конфиг: per-role model ID, ключ (через backend), temperature/лимиты, политика ретраев и фоллбэка (rate-limit/недоступность free-моделей → бэкофф → запасная модель из конфига; логировать, кто реально ответил). Контексты под раздувшиеся промпты v1.1 достаточны: Qwen 262K, Super/Ultra 1M, Hermes 131K; единственное узкое место — Venice 33K (см. фоллбэк выше).

## 7. Распределение правил и состав промптов (движок vs LLM)

Ключевое для качества: что детерминированно — в движок; что про суждение/тон/голос — в промпт нарратора.

### 7.1 Где живёт каждый файл правил

| Файл | В движке (код/конфиг) | В промпте | Комментарий |
|------|------------------------|-----------|-------------|
| `systems.md` (бой/время/экономика) | **да** (таблицы, кости, цены, скорости, раны, усталость, время) | стиль описания боя | числа считает движок |
| `magic.md` | состояние Силы, пороги тёмных дуг, проверки каста | школы как «языки», суждение о тёмной цене, зрелищность | гибрид |
| `progression.md` | скрытые счётчики практики, триггеры особенностей/специализаций | формулировка особенностей словами | гибрид |
| `world.md` | деньги, расы (сроки/модификаторы), регионы (множители) | тон, атмосфера, лор | гибрид |
| `religions.md` | домены/легальность как данные | поведение культов, реакции, инквизиция | гибрид |
| `master.md` | чек-листы как guardrails валидатора | философия ведения, «не действуй за игрока», формат сцены | гибрид |
| `creation.md` | флоу создания, броски, потолок старта | первые слова мастера | раздел 5 |
| `commands.md` | поведение `/go /save /ask` | — | раздел 13 |

### 7.2 Состав системного промпта по ролям

Каждый вызов = **статический системный промпт** (из правил, под роль) + **динамический scoped-контекст** (из движка) + **tool-схема**.

- **Ведущий:** философия и стиль из `master.md`/`world.md`; правила-выдержки релевантной школы/боя/экономики; **активные модули персонажа** (чтобы не предлагал магу-воину каст); запрет действовать за игрока; формат сцены + блок статуса. Динамика: сцена, последние ходы, RAG-факты, полные карточки NPC в сцене, исходы бросков от движка.
- **Нормализатор/валидатор:** на вход — `propose_ops` нарратора + правила-выдержки guardrails. Задача: привести «плавающие» операции к чистой схеме `Op[]` и семантически отловить утечки знания в репликах NPC (NPC сослался на факт вне своего `known_by` → отклонить/перегенерировать). Возвращает только нормализованные `Op[]`. Детерминированные проверки на нём НЕ висят (см. 7.3).
- **Режиссёр:** философия арок/хуков из `creation.md`/`progression.md`; запрет повторять `motifs_used`; матрица осей; состояние мира и героя.

### 7.3 Разделение проверок: движок (код) vs валидатор (LLM)

Чтобы не грузить LLM детерминируемым и не плодить ошибки:

| Проверка | Где |
|----------|-----|
| Инвентарь-дифф (набор = прежний ± явные операции), заряды | **движок (код)** |
| Логика капитала, цены в диапазонах, «неоткуда взявшиеся» находки | **движок (код)** |
| Гейтинг модуль-операций (`power.set` без модуля `magic` и т.п.) | **движок (код)** |
| `npc.alter_core` только с причиной; жёсткие правила scope (`secret`/`known_by`) | **движок (код)** |
| `darkcost.advance` только за переступающее (порог) | **движок (код)** + суждение нарратора |
| Нормализация формата tool-call'ов в `Op[]` | **валидатор (LLM)** |
| Семантическая утечка знания в тексте реплики NPC (№3) | **валидатор (LLM)** |
| Суждение о тоне, голосе NPC, зрелищности, тёмной цене | **нарратор (LLM)** |

## 8. Поток хода (turn pipeline)

1. **Ввод игрока** (намерение/реплика/действие).
2. **Сборка scoped-контекста** (движок): сцена из `session`; последние N ходов; RAG-выборка релевантных `facts`/`npc`/`relationships`/`contracts`/`timers`; полные карточки NPC в сцене (всегда дословно); выдержки правил по нужде; **список активных модулей** персонажа.
3. **Броски/механика, если действие требует** (раздел 9): результат → в контекст как факт исхода.
4. **Вызов Ведущего** (tool-схема): проза + `propose_ops`.
5. **Нормализация (валидатор LLM):** «плавающие» `propose_ops` → чистые `Op[]`; семантическая ловля утечек знания в репликах NPC (7.3).
6. **Детерминированные проверки + применение (движок):** прогон проверок из 7.3 (инвентарь-дифф, капитал, гейтинг модулей, scope, порог тёмной цены) → атомарно применяет состояние; пишет ход в `chronicle`; двигает таймеры/мировые часы; проверяет fire-условия `seeds`. Невалидное — отклоняет/откатывает с логом.
7. **Рендер игроку:** проза + блок статуса (адаптивный под модули, раздел 18).
8. **Персист:** IndexedDB; по `/save`/автосейву — экспорт JSON+md и `git commit`.

### 8.1 Контракты операций (tool-calls), минимум

```
narrate(prose, ops: Op[])

Op =
  | capital.change {delta, reason}
  | item.add {item} | item.remove {id, qty, reason} | item.update {id, fields}
  | hp.change {delta, reason} | stamina.change {delta, reason}
  | status.add|status.remove {effect, ...}
  | reputation.shift {faction, axis, delta, reason}        // скрыто, нарратив наружу
  | fact.add {text, scope, known_by, tags}
  | npc.relationship {from, to, axis, delta, notes}
  | npc.spawn {seed_card} | npc.alter_core {id, fields, cause}
  | contract.offer|contract.update|contract.close {fields}
  | location.note {id, fields}
  | timer.add|timer.fire {...}
  | feature.grant {name, description} | specialization.offer {options[]}
  | // модуль-зависимые:
  | power.set {state}                                      // только если активен magic
  | darkcost.advance {arc, reason}                         // только переступающее
  | heat.change {delta, reason}                            // только если активен intrigue
  | faith.shift {delta, reason}                            // только если активен faith
  | craft.progress {fields}                                // только если активен craft
```

Движок применяет только провалидированные `Op`; модуль-зависимые операции отклоняются, если соответствующий модуль не активен.

## 9. Игровые подсистемы движка

### 9.1 Броски и честность

D20 + скрытые модификаторы на стороне движка; честный RNG; игрок цифр и DC не видит. LLM **не решает** успех — получает исход. Раскрытие — только через `/ask`.

### 9.2 Бой (расширенно; критично для не-магов)

- **Непрерывное время, одновременность** — без раундов/инициативы. Движок ведёт **скрытое** время действий (скорости из `systems.md`: кинжал 1–2с, меч 2–3с, двуручный 4–5с, лук 3–4с, сближение 5м 2–3с…), чтобы решить, кто успел раньше.
- **Атрибуты/HP/выносливость** — скрыты; AC по стилю (агрессивный/обычный/оборонительный/только защита/безрассудный); ситуационные модификаторы; крит/провал по `systems.md`.
- **Раны по % HP** (лёгкая/средняя/тяжёлая/критическая/смерть) со штрафами и кровотечением; усталость копится; **мораль** врагов (раненые/брошенные бегут или сдаются).
- **Каст в бою:** занимает время, требует концентрации; урон по касту → скрытая проверка концентрации (DC=max(10, урон/2)); черпающим легче сорвать.
- **Поток:** движок описывает (через нарратора) **действия врага, не тайминги**; не спрашивает «продолжаешь?»; успел враг сблизиться — бьёт, не успел — первым бьёт игрок; «кто быстрее» решается скрыто и подаётся повествованием.
- **Смерть значима** (раздел 14).

### 9.3 Магия (модуль `magic`)

Активируется только при наличии модуля. Единый ресурс **Сила** (enum, скрыто/грубо: Полон/Расходует/На исходе/Истощён). Два типа магов (черпающий/своесильный) — влияют на восстановление и срываемость каста. **Свободный каст по школам** (намерение → три оси: Сила/воображение/мастерство → скрытый бросок → успех/«да, но…»/искажение). Каст тратит Силу **и** выносливость. **Тёмные цены** — редкие необратимые дуги (коррупция/деградация/распад памяти/годы жизни): двигаются только `darkcost.advance` за переступающее, показываются нарративом. Рутина их не трогает.

### 9.4 Репутация и узнавание

- **Шкала по фракциям** (Почитаемый/Легендарный … Враг/Заклятый враг) — данные, скрыто; манифестация — нарративом (цены, отказы, проверки, взгляды, доносы), без таблиц на экране.
- **Сдвиги (скрыто):** помощь/подарок/спасение/уважение ↑; угроза/обман/отказ/вред ↓; модификаторы — раса, внешний вид, известная репутация.
- **Известность** (отдельно от тайной идентичности): высокая → героя узнают в лицо/по делам (влияет на `known_by` при появлении NPC); «неизвестен» → не узнают. **Связь с №3:** NPC опознаёт тайну героя только если факт в его `known_by` **или** известность/репутация это объясняют. Тайный некромант с репутацией «неизвестен» не опознаётся случайным трактирщиком — по построению.

### 9.5 Экономика (резолвер цен)

Цена = базовый диапазон категории (`systems.md`) × множитель региона × сезон × торг(CHA/связи). Движок выдаёт конкретную цену из диапазона консистентно; валидатор сверяет любые `capital.change` и находки на логичность (никаких «нашёл 1000 золотых» без источника). Вес денег, банки/расписки для крупных сумм — как сюжетный фактор.

### 9.6 Время и путешествия

Движок ведёт **день + время суток + сезон**; быт сворачивается в строку (без счётчиков голода/гигиены). Время суток влияет на доступность лавок/служб, опасность ночи, видимость. Путешествия — по скоростям/модификаторам `systems.md` (пешком/верхом/повозка/корабль; груз/броня/дорога/погода). Встречи в пути — по необходимости (где создают историю), не «каждые 20 км». Заживление ран и восстановление Силы/выносливости — по таблицам `systems.md`. Активные **таймеры** (контракты, заживление, события) движок проверяет каждый ход.

### 9.7 Контракты / квесты

`contracts[]`: `{id, title, giver_npc, status: предложен|активен|выполнен|провален|отказ, objectives[], reward, deadline_day, faction, notes}`. Операции `contract.offer/update/close`. Дедлайны — в таймеры. Завершение влияет на репутацию/отношения/капитал. Сохранять значимые; разовые мелочи — нет.

### 9.8 Локации

`locations[]`: `{id, name, region, type, properties, known_npcs, notes}`. **Политика сохранения** (`master.md`): сохранять, если хоть одно — база/штаб, схрон, посещается 3+, важна для контракта, ключевое событие, живёт важный NPC, уникальные свойства. Разовые проходные — не сохранять. Детализация: базы/схроны — максимум, контракты — высоко, прочее — минимум.

### 9.9 Генерация NPC

Проходной NPC — процедурно (тип→имя по расе→возраст→черта→мотивация→стартовое отношение с учётом расы/вида/репутации героя), операция `npc.spawn`. **Назначить scope знания при спавне** (что этот случайный человек знает публично; тайны героя — нет). Персистить в `npc` только значимых (`master.md`); проходных — эфемерно в рамках сцены. Важных детализировать (ядро + секрет), проходных — одной строкой.

### 9.10 Отложенные последствия (seeds) — мир помнит

`seeds[]`: `{id, description, trigger: {type: time|location|faction_threshold|random|flag, params}, payload, tags, planted_day}`. Движок/Режиссёр проверяют fire-условия каждый ход/тик и при срабатывании разворачивают (слух, возвращение преданного NPC, инквизиция задаёт вопросы после тёмной магии, наступивший долг). Чек-лист «что мир запоминает» (`progression.md`): репутация, отношения, финансы, время, сюжет, мораль/психика, магия, религия, тело, статус. Лучшие последствия — отложенные; держать баланс (не всё катастрофа).

### 9.11 Прогрессия (три слоя)

- **Слой 1 — скрытый уровень:** числовые характеристики/мастерство растут тихо от практики (движок ведёт счётчики применений/боёв/кастов).
- **Слой 2 — особенности словами:** после серии похожих действий/кризиса — `feature.grant` редко и художественно («Опытный переговорщик», «Фехтовальщик», рост мастерства школы). Касается всех сборок.
- **Слой 3 — специализации:** очень редко, после критического события — `specialization.offer` (выбор из 2–3), меняет стиль игры.
- Бытовые навыки (грамотность, верховая езда, языки) — не «курсами с таймерами», а строкой по логике. Значимый рост (бой/ремесло/магия) требует учителя/времени/практики; учитель может отказать.

## 10. RAG / ретривал (решает №2)

При создании `fact`/`npc`/`chronicle` — эмбеддить и класть в локальный векторный индекс (рядом с состоянием/в IndexedDB; пересборка из git при синке). Перед сборкой контекста — запрос по эмбеддингу от сцены + ввода; top-k релевантных фактов/NPC/отношений/контрактов/таймеров. Полные карточки NPC в сцене — всегда дословно (вне top-k). Эмбеддер мультиязычный, сильный в русском; **проверить русский recall** до релиза; компонент сменный.

## 11. Команды

- **`/go`** — `git pull` → собрать `session` → краткий отчёт (формат `commands.md`, блок статуса адаптивен под модули) → ждать подтверждения → продолжить **без** автопрогрессии времени.
- **`/save`** — экспорт JSON-канона + md-рендер → `git commit` → краткий отчёт. **Файлы правил не трогаются** (read-only).
- **`/ask`** — мета-режим: движок отдаёт «под капот» (скрытый бросок, Сила числом, причина реакции NPC, почему выдана особенность, сдвиг репутации). Единственное окно к скрытой кухне; читает внутренний лог хода.

Файлы правил подключаются как статичный read-only контент; в промпты — выдержками по нужде (бюджет токенов), не целиком.

## 12. Анти-повтор, Режиссёр, мир-симуляция (решает №1)

- **`arcs` с тегами** (тема × фракция × регион × тип антагониста × структура + `motifs_used`).
- **Режиссёр** (между арками): на вход — `arcs` + `world_state` + герой + активные `seeds`; на выход — следующая арка из **неиспользованной** комбинации, без повтора `motifs_used`; результат — мягкий хук для Ведущего, не приказ.
- **Мир-симуляция** (офлайн-тики по мировым часам): фракции/регионы двигаются сами (события, конфликты, сдвиги цен/власти), пишут `world_state` и порождают `public`-факты/слухи и новые `seeds`. Новизна — из симуляции, а не из выдумки модели. Частоту/вес событий ограничить конфигом (баланс `progression.md`).

## 13. Совместимость с исходным дизайном

Философия ведения (`master.md`), потолок старта (`creation.md`), нарративные последствия (`progression.md`) переносятся без изменений — ТЗ задаёт, как исполнять их программно.

## 14. Смерть и провал

0 HP = смерть; как правило окончательна, без сюжетной брони. Исключение — светлая магия высшего порядка (воскрешение в узком окне ценой лет жизни). В приложении при смерти персонажа:
- зафиксировать исход в `chronicle` + финальная сцена;
- предложить: **откатиться к более раннему коммиту** (git checkout — честный «загруз»), либо **новая игра**. Движок не воскрешает по прихоти.
Провал контракта/ареста/изгнания — не конец игры, а последствие (репутация, сюжет, seeds).

## 15. Сохранение, загрузка, синхронизация

- **Канон — структурный JSON в git-репо**; md — производный экспорт для чтения. У состояния `schema_version`; при изменении схемы — миграция старых сейвов (обязательно, т.к. сейвы живут в git долго).
- **Новая игра** — флоу раздела 5. **Продолжить** — указать git-репо/ветку или импорт сейв-бандла (zip JSON+md). «Загрузка как в любой игре».
- **Мульти-кампании:** разные персонажи/прохождения — разные ветки или директории репо; UI даёт список кампаний.
- **Синк:** `pull` при открытии, `commit` при сохранении/автосейве; один пользователь → конфликтов почти нет; при расхождении — предупреждение и выбор версии (последняя по времени по умолчанию). Файлы правил — защищённая директория, не перезаписываются.
- **Версионирование/откат** — из git (сейв = коммит; «к Дню X» = checkout).

## 16. Критерии приёмки (проверяемые тесты)

1. **№5 — инвентарь:** 15+ предметов (вкл. артефакты) → 10 циклов `/save`+`/go` на разных устройствах → набор и заряды идентичны ± явные операции. Необъяснённая пропажа = провал.
2. **№3 — scope знания:** тайный некромант (репутация «неизвестен», тайна в `secret`) у нового трактирщика → **не** опознан. Добавить факт в `known_by` трактирщика → опознан при следующей встрече. Оба исхода корректны.
3. **№4 — идентичность NPC:** прогон 300+ дней (скриптом) → запертое ядро ключевых NPC не дрейфует; изменения только через залогированные `npc.alter_core` с причиной.
4. **№2 — память:** 50 мелких фактов в разных сессиях → через 100+ ходов запрос связанных → подтягиваются и используются (recall ≥ порога; мерить на русском).
5. **№1 — анти-повтор:** 20 арок подряд → доля повторных комбинаций ниже порога; Режиссёр не предлагает `motifs_used`; seeds срабатывают отложенно.
6. **R1 — сборко-агностичность:** пройти стартовые сцены **воином** и **шпионом** без модуля магии → нигде не предлагается каст; UI не показывает Силу; статус/гроссбух адаптированы под combat_mastery / intrigue. Боевой маг показывает оба модуля.
7. **Кросс-девайс:** ход начат на ПК, сохранён, продолжен на планшете с того же момента.
8. **Тёмный контент:** сцена с инквизицией/кровью без необоснованного отказа (при нужде — фоллбэк-профиль).
9. **R2 — честная механика:** кости/цены/исходы боя приходят от движка; LLM не «подыгрывает» (проверка по логам `/ask`).

## 17. Контент и зрелость

Приватный одиночный инструмент для взрослого пользователя; мир по дизайну тёмный (инквизиция, кровь, пытки, культы) — это художественная зрелость фэнтези. Поэтому: **не** ставить модель-цензор в горячий путь (она режет легитимный нарратив); при отказе основной модели на тёмной сцене — переключаемый фоллбэк-профиль. При этом инструмент остаётся ролевой игрой: он не предназначен для генерации реально-вредного контента вне художественной рамки (инструкции по реальному причинению вреда и т.п. — вне задачи). Хард-линии и фоллбэк-триггеры зафиксировать в конфиге.

## 18. Фронтенд: визуальное оформление и связь с backend

### 18.1 Концепция

Интерфейс — **живая хроника, которая пишет себя сама** (продолжение путевого дневника героя): главный экран = поток прозы, механика проступает на полях. Сознательно уводит от дефолтных AI-обликов (кремовый+терракот; чёрный+кислотный; газетные колонки). **Hero — сама проза** (первая сцена при новой игре), не дашборд.

### 18.2 Токены (dark-first; светлая «скрипторий»-тема вторична)

| Токен | Hex | Назначение |
|---|---|---|
| `ink-900` | `#0E1116` | фон (сине-чёрная тушь) |
| `ink-800` | `#161B24` | панели/карточки |
| `vellum-100` | `#E7E2D4` | текст прозы (тёплый пергамент) |
| `vellum-300` | `#A9A491` | вторичный текст |
| `moon-300` | `#C5CEDC` | акцент (ссылки, выделения) |
| `accent-400` | `#4FD6C9` | **сигнатурный** акцент «нити состояния» |
| `dark-700` | `#7A2E3B` | тёмные дуги/угроза — редко и веско |

**Типографика** (кириллица обязательна; роли по смыслу): дисплей — `Spectral`/`Literata` (сдержанно); тело-проза — `Literata` (долгое чтение, 60–75 знаков/строка); утилита/механика — моноширинный с кириллицей (`JetBrains Mono`/`IBM Plex Mono`) для статуса/таймеров/капитала/полей карточек. Раскол «антиква=проза / моно=механика» зеркалит раскол «нарратор/движок».

### 18.3 Сигнатура — «нить состояния» (сборко-агностичная)

Тонкая светящаяся линия в gutter между прозой и гроссбухом, **кодирующая главный ресурс-риск конкретной сборки** (не только мага):
- **magic** → Сила (яркость/плотность ↔ Полон/Истощён; пульс у Места Силы);
- **combat_mastery** → выносливость + раны (нить «трескается»/краснеет с ранами);
- **intrigue** → «след/подозрение» (heat): обычно тусклая = низкий профиль, разгорается/краснеет, когда мир подбирается;
- **faith** → вера/служение (теплеет/холодеет с грехом/благодатью);
- **боевой маг** → две переплетённые нити (Сила + выносливость).

Второй штрих — «оседание чернил» (стрим прозы + лёгкий fade-settle) и подсветка применённых дельт в гроссбухе. При `prefers-reduced-motion` анимации письма отключаются.

### 18.4 Макет

Центрированная колонка-хроника (hero); справа сворачиваемый «гроссбух» состояния (рендерит **только активные модули**); нить состояния в gutter; внизу композер с чипами `/go /save /ask`.

### 18.5 Компоненты

Поток хроники; композер (Enter — отправка, Shift+Enter — перенос); **адаптивный блок статуса** (всегда: день/время/локация/HP/выносливость/капитал; условно: Сила — если magic, «след» — если intrigue, вера — если faith); гроссбух с модуль-зависимыми панелями; карточка NPC (ядро + живой слой без скрытых полей героя); панель `/ask` (моно, `ink-800`, явно «вне мира»); индикатор синка; экраны сейвов (Новая игра — флоу раздела 5; Продолжить — git-репо/импорт; список коммитов = точки сохранения; список кампаний); **первый запуск (онбординг):** ключ OpenRouter → синк (git-репо/токен) → выбор моделей (или дефолты) → Новая игра/Загрузить; настройки (модель на роль, режим синка, эмбеддер, тема, размер текста).

### 18.6 Связь с backend (контракт)

Фронт держит движок и состояние; к backend — **только за LLM и эмбеддингами**. Backend stateless.
- `POST /llm/{role}` (`narrator|validator|director`): промпт (собранный движком) + tool-схема; **ответ стримом** (SSE) для эффекта письма; backend подставляет ключ, ретраи/фоллбэк, в метаданных — какая модель ответила.
- `POST /embed` (если эмбеддер в backend, иначе не нужен).
- `GET /health` — доступность + раскладка моделей.

**Поток UI:** ввод → реплика сразу в хронику (оптимистично) + «Мастер пишет…» → `narrator` (стрим, «оседание чернил») → `validator` (фоном) → движок применяет дельты → **гроссбух анимирует дифф**, статус из состояния движка (не из прозы) → автосейв/`commit` → тост «Сохранено — День X». Режиссёр (`director`) — вне горячего пути, ненавязчивый бейдж.

**Состояния голосом интерфейса** (активный залог, единый словарь): нет сети — «Мир замер: нет связи с моделью. Ход не отправлен — попробуйте снова.»; throttle — «Модель занята — перехожу на запасную…»; отказ на тёмной сцене — предложить переключить профиль; пустая хроника — приглашение (первая сцена + «Что делаешь?»). Кнопки именуются действием и держат имя по флоу («Сохранить»→«Сохранено», «Продолжить», «Спросить мастера»).

### 18.7 Планка качества

Адаптивность до планшета/телефона; видимый фокус с клавиатуры; `prefers-reduced-motion`; контраст AA; регулируемый размер текста; светлая/тёмная темы; офлайн-доступ к оболочке и состоянию (LLM-ходы требуют сети — понятное сообщение).

## 19. Нефункциональные требования

- **Латентность хода:** дефолт = 2 LLM-вызова (Ведущий + Валидатор) + локальный RAG; Режиссёр/мир-тики — асинхронно; индикатор генерации.
- **Free-тариф OpenRouter:** ретраи с бэкоффом → фоллбэк-модель; логировать ответившую модель.
- **Приватность ключа:** в backend; прямой вызов из PWA — опционально и осознанно.
- **Офлайн:** оболочка и состояние офлайн; LLM-ходы требуют сети.
- **Бюджет контекста:** правила и холодная хроника — выдержками/ретривалом, не целиком; следить за длиной промпта по роли.
- **Логи хода** (для `/ask` и отладки): броски, дельты, какие факты в scope, активные модули.

## 20. Этапность (рекомендуемый порядок)

- **Фаза 0 — каркас:** PWA, backend-прокси, git-синк, конфиг ролей, первый запуск; базовый UI (хроника, композер, стрим). Ход «ввод → Ведущий → проза» без состояния.
- **Фаза 1 — общий слой + дельты (чинит №5):** core-персонаж, инвентарь/капитал, операции, транзакции, валидатор инвентаря, `/save`+`/go`, адаптивный блок статуса + гроссбух + нить состояния.
- **Фаза 2 — создание персонажа + модули (R1):** флоу раздела 5, проверка таланта, маппинг направление→модули, модуль-зависимые операции/UI; тест «воин/шпион без магии».
- **Фаза 3 — карточки + scope + RAG (чинит №2, №3, №4):** запертые NPC, модель знания, эмбеддинги, scoped-контекст, guardrails валидатора, генерация NPC.
- **Фаза 4 — подсистемы:** бой-резолвер, репутация/узнавание, экономика, время/путешествия, контракты, локации, прогрессия (3 слоя), `/ask`.
- **Фаза 5 — Режиссёр + мир-симуляция + seeds (чинит №1):** теги арок, планировщик, офлайн-тики, отложенные последствия.
- **Фаза 6 — полировка:** фоллбэк-профили, ретраи, кросс-девайс, UI (анимации/темы/доступность/экраны сейвов/кампании), миграции схемы, прогон критериев приёмки.

## 21. Открытые вопросы / риски

## 22. Логи и отладка (патч 1.2)

Подсистема логирования (полный текст патча — `docs/logs_patch.md`). Принцип: логи
пишет **движок** детерминированно в NDJSON; модели — субъекты логирования, не авторы.

- **22.1** Структурно (NDJSON, append-only), сквозная корреляция `session_id`/`turn_id`/`seq`; логи ≠ состояние (вне git-канона).
- **22.2** Событие: `{ ts, session_id, turn_id, seq, type, level, payload }`.
- **22.3** Типы: `input`, `context_assembled`, `mechanics`, `llm_call`, `proposed_ops`, `validation`, `applied_ops`/`state_diff`, `worldsim`, `persist`/`sync`, `warn`/`error`.
- **22.4** Уровни trace/debug/info(деф)/warn/error; полные промпты — только debug/trace.
- **22.5** Локально (IndexedDB), ротация по числу; не выгружать автоматически.
- **22.6** Bug-bundle: последние K событий + снапшот состояния + конфиг (экспорт файлом).
- **22.7** `/ask` — курируемое окно игрока в тот же лог.

**Связки (B1–B4):** §8 — шаг «лог хода»; `/ask` читает NDJSON-лог; НФТ «Логи и отладка» = раздел 22; логирование в каркасе.

**Реализация:** `apps/web/src/lib/logbus.svelte.ts` (ring + IndexedDB-зеркало);
инструментированы клиент LLM (`llm_call`), пайплайн хода (`input`/`proposed_ops`/
`applied_ops`/`state_diff`/`validation`/`worldsim`/`error`), бой (`mechanics`),
`/save` (`sync`). UI: уровень логов + экспорт bug-bundle в настройках; `/ask` читает лог.
